# MoorDyn v1 – MATLAB prescribed-kinematics coupling

This repository provides a MATLAB interface for running MoorDyn v1 with a
prescribed six-degree-of-freedom motion time history.

The coupling is **one-way**: MATLAB sends the imposed body position,
orientation, and velocity to MoorDyn at each time step. MoorDyn calculates the
mooring-line response, forces, and tensions, but those loads do not modify the
input motion. This makes the project useful for replaying measured or
previously calculated kinematics and comparing the resulting mooring loads
with experimental data.

A typical use is tuning `Mooring/lines.txt`. Because the same motion history
can be replayed quickly, line properties, geometry, discretization, damping,
drag coefficients, and solver settings can be changed and tested in rapid
succession. This supports fast iteration of the mooring configuration without
rerunning the experiment, CFD calculation, or other simulation that produced
the body motion.

## Experimental data and citation

The example motion and mooring-load data are derived from an experimental
campaign on a taut-leg mooring system for a 1:96-scale DeepCWind
semi-submersible floating offshore wind turbine. The complete experimental
dataset is publicly available from 4TU.ResearchData and can be downloaded by
anyone:

- [Experimental dataset of taut-leg mooring system for FOWT](https://data.4tu.nl/datasets/9f32fe66-ec63-4cad-bf6a-7e9fe62d68e8)
- Dataset DOI: [10.4121/9f32fe66-ec63-4cad-bf6a-7e9fe62d68e8](https://doi.org/10.4121/9f32fe66-ec63-4cad-bf6a-7e9fe62d68e8)

The experimental campaign and dataset are described in:

> S. Schreier, "Experimental investigation and dataset release of a taut-leg
> mooring system for a semi-submersible floating offshore wind turbine,"
> *Ocean Engineering*, vol. 328, 121067, 2025.
> [https://doi.org/10.1016/j.oceaneng.2025.121067](https://doi.org/10.1016/j.oceaneng.2025.121067)

## Repository contents

| File or folder | Description |
| --- | --- |
| `LAUNCHER_MoorDyn_Imposed.m` | Example launcher. It loads the motion data, creates the prescribed `N × 6` kinematics matrix, and calls the coupling function. |
| `FUNC_MoorDyn_imposed.m` | Main MATLAB-to-MoorDyn interface. It loads the MoorDyn library, initializes the model, advances it through the imposed motion, and closes the library. |
| `Plot_Output.m` | Reads the MoorDyn output files, compares selected line tensions with the reference data, and can animate the line-node positions. |
| `094_cutted.mat` | Example motion and experimental-load data used by the launcher. |
| `MoorDyn.dll` | Compiled 64-bit Windows MoorDyn v1 library used by MATLAB. |
| `MoorDyn.h` | C interface header used by MATLAB when loading `MoorDyn.dll`. |
| `Mooring/lines.txt` | MoorDyn model definition: line types, nodes, lines, environmental properties, and solver options. |
| `Mooring/Lines.out` | MoorDyn system-level output generated by a run. |
| `Mooring/Line*.out` | MoorDyn line-level outputs containing time histories, node positions, and requested line quantities. |
| `Mooring/Line*.csv` | Copies of the line output files generated by `Plot_Output.m` for convenient import with `readmatrix`. |
| `Mooring/094_cutted.mat` | Copy of the reference data used by `Plot_Output.m` after it enters the `Mooring` directory. |
| `Pubblications/` | Open-access paper describing the experimental campaign and released dataset. |
| `RunMoorDyn_experimental.asv` | MATLAB autosave of an earlier experimental script. It is retained as a development reference and is not required by the main workflow. |
| `ReadMe.txt` | Legacy notes describing earlier mooring-configuration variants. |

## Requirements

- MATLAB with support for `loadlibrary`, `calllib`, `libpointer`, and
  `unloadlibrary`.
- A supported C/C++ compiler configured in MATLAB for parsing and loading the
  C library interface. If needed, configure it with:

  ```matlab
  mex -setup C++
  ```

- A MoorDyn v1 shared library compatible with the operating system and MATLAB
  architecture. The included `MoorDyn.dll` is for 64-bit Windows.

MoorDyn is third-party software distributed under the GNU GPL v3. See the
copyright and license notice in `MoorDyn.h` and the upstream
[MoorDyn repository](https://github.com/FloatingArrayDesign/MoorDyn).

## Input kinematics

`FUNC_MoorDyn_imposed` expects:

```matlab
FUNC_MoorDyn_imposed(dt, kin)
```

where:

- `dt` is the constant coupling time step in seconds;
- `kin` is an `N × 6` matrix containing the prescribed motion.

The columns of `kin` are:

| Column | Degree of freedom | Unit |
| --- | --- | --- |
| 1 | Surge | m |
| 2 | Sway | m |
| 3 | Heave | m |
| 4 | Roll | rad |
| 5 | Pitch | rad |
| 6 | Yaw | rad |

The launcher converts the rotational measurements from degrees to radians.
The coupling function calculates translational and angular velocities using a
first-order finite difference:

```matlab
kin_d = diff(kin)./dt;
```

The time spacing in the input history must therefore be constant and equal to
`dt`.

## Running the example

1. Start MATLAB and set the current folder to the repository root—the folder
   containing `MoorDyn.dll`, `MoorDyn.h`, and the `Mooring` directory.

2. Check the settings in `LAUNCHER_MoorDyn_Imposed.m`:

   ```matlab
   load 094_cutted
   IMAX = 3000;
   ```

   `IMAX` selects how many samples of the input history are simulated. Reduce
   it for a shorter test, or replace it with the length of your dataset.

3. Run:

   ```matlab
   LAUNCHER_MoorDyn_Imposed
   ```

4. MoorDyn reads `Mooring/lines.txt`, performs its initial-condition dynamic
   relaxation, advances through the imposed kinematics, and writes its output
   files under `Mooring`.

5. To inspect the results, run:

   ```matlab
   Plot_Output
   ```

`Plot_Output.m` compares the first three MoorDyn line-tension histories with
`Res.MooringLine1`, `Res.MooringLine2`, and `Res.MooringLine3` from the example
dataset.

To animate the mooring-line nodes in the horizontal/vertical plane, change:

```matlab
plotflagTIME = 0;
```

to:

```matlab
plotflagTIME = 1;
```

The plotting script deletes existing `Mooring/Line*.csv` files and recreates
them from the current `Line*.out` files. Preserve any CSV results you need
before rerunning it.

## Using another motion history

Replace the example data loading and field mapping in
`LAUNCHER_MoorDyn_Imposed.m`. The resulting `kin` matrix must remain `N × 6`,
with translations in metres and rotations in radians. For example:

```matlab
dt = time(2) - time(1);

kin(:,1) = surge;
kin(:,2) = sway;
kin(:,3) = heave;
kin(:,4) = deg2rad(roll);
kin(:,5) = deg2rad(pitch);
kin(:,6) = deg2rad(yaw);

FUNC_MoorDyn_imposed(dt, kin)
```

Update `Mooring/lines.txt` to describe the corresponding mooring system. The
MoorDyn internal time step `dtM` should be smaller than or equal to the MATLAB
coupling time step `dt`.

For calibration work, keep the imposed kinematics unchanged between runs,
modify one or more parameters in `lines.txt`, rerun the launcher, and compare
the new `Line*.out` histories with the reference measurements using
`Plot_Output.m`.

## Outputs and limitations

The current coupling function does not return a MATLAB result structure. Its
primary outputs are the files requested in `Mooring/lines.txt`, including
`Lines.out` and `Line*.out`. The `LinesCalc` force vector and fairlead-tension
history are calculated internally but are not returned by
`FUNC_MoorDyn_imposed`.

Because the motion is prescribed, the calculated MoorDyn forces and moments
cannot alter the body trajectory. A two-way simulation would require a motion
solver that advances the body dynamics using the MoorDyn loads at every
coupling step.

Always close and unload the MoorDyn library after a run. The coupling function
does this automatically and also attempts to close a previously loaded copy
before initialization.
